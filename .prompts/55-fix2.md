# Fix — task 55, review two

`/tmp/55-rr2.log` failed `ace5a53`. Three findings, all real: the button can be visible with the box below the
fold, and then it is inert; a non-zlive `http:` embed is still framed as mixed content; the footer audience is
announced twice on top of the link's label.

## 1. An unmounted button is always a Play

The failure comes from `frameMounted` being false when the box is merely below the fold, while the footer sits
*above* the box and is visible. The button then does nothing.

- Label by mount state, not just the hold: unmounted → `Play`; mounted and muted → `Sound on`; mounted with sound
  → `Mute`. Unmounted means Play in every case, including the 200 % small screens, landscape and stale.
- A tap while unmounted always mounts muted: set the started flag, then bring the player box into view
  (`scrollIntoView({ block: 'nearest' })`) so the frame is actually seen, and let the observer mount it. Tapping
  again then gives sound as today.
- Rename `playRequested` to something that says opt-in, and reset it on a hero change (uri_name) as well as
  resetting sound, so a different event under Save-Data needs its own Play.
- Save-Data turning on mid-session must not tear down a frame the user is already watching or hearing: once
  started, the hold no longer applies for the visit.
- Focus stays on the button through the Play mount, and the label follows the mount, not the tap.

## 2. `http:` for every embed, not just zlive

`resolveHeroEmbed` must upgrade every resolved embed to `https:` (as it already does for zlive), so a taifood
`http:` iframe or a `zlive.st:443` one is framed over https. A `/embed` path that is already zlive keeps the
existing normalisation (credentials and trailing slash dropped). Test a taifood `http:` iframe, a zlive `http:`
and a zlive `:443`, and confirm the frame `src` never starts `http:` on an https page.

## 3. Announce the audience once

The link's accessible label already ends with the count, so the footer's audience span is a duplicate. Mark the
footer audience `aria-hidden="true"` (the button stays announced). Keep the visible text.
