# Fix — task 58, sixth pass: stop segmenting, let the browser break

`3888e12` on `task/58-banner-clean`. Review five is `/tmp/58-rr5.log`.

## The pattern

Five rounds, five fails, all in the same corner: the status text is hand-split into `.banner-status-word` spans so
the fallback must reimplement Unicode line breaking. Each fix exposed another script — Thai `ำ`, then Hangul
conjoining jamo (`후반전` → `ᄒ ᅮ ᄇ ᅡ ᆫ ᄌ ᅥ ᆫ` on the server, `후 ᆨ` even after hydration). The reviewer found
Devanagari and Khmer splits behind it, and Prepended_Concatenation_Mark. There will be more.

Browsers already do this correctly, natively and in every script: line breaking never splits a grapheme cluster,
Thai breaks at dictionary words, CJK between characters, Latin at spaces. The spans exist only so the fit pass can
measure the widest unbreakable unit. So measure it with the browser instead of reproducing it.

## Change

1. **Drop the tokenisation.** `statusWords`, `wordSegmenter`, `segmentAfterHydration`, `unspacedScript`,
   `clusterTail`, `fallbackClusters` and the `v-for` word spans all go; a tier renders its text again. Remove
   `.banner-status-word` from `theme.css`. SSR and client markup become identical by construction — say so in the
   docs and keep the hydration-error assertion.
2. **Measure the widest unbreakable unit with the layout engine.** For each status line, set
   `white-space: normal; width: min-content`, read the width, then restore. That is exactly the widest chunk the
   browser will refuse to break, in whatever script, with no tables and no Segmenter. Keep the existing
   `+ 1` slack.
3. Keep the monospace fallback for a single unit wider than the full row, driven by that measurement.
4. Wrapping stays native: `[data-wrap]` keeps `white-space: normal`, the `100% / floor` width and
   `text-wrap: balance`. Do not add `overflow-wrap: anywhere` or `word-break`.

## Tests

   text still equals the source exactly. Run it for state, detail and audience in SSR, fallback and hydrated
